Shortened the [frontend README](frontend/README.md) and added the proxy rationale. Formatting passes.

The browser requests `/api/companies/AAPL/filings`. Vite forwards that to backend port 3001 as `/companies/AAPL/filings`. This:

- Distinguishes API requests from the frontend’s identical `/companies/:ticker/filings` route.
- Keeps browser requests on the same origin, avoiding CORS configuration.
- Requires equivalent forwarding in production; Vite’s development proxy isn’t included in the build.

The types currently compare as follows:

| Type | Frontend versus backend | Share? |
|---|---|---|
| `Filing` | Identical fields and nullability | Yes |
| `FilingsResponse` | Explicit frontend interface; matching backend return shape is inferred | Yes |
| `FilingsFilters` / `FilingQuery` | UI uses empty string for “all” and fixed page size; backend uses optional `form` and explicit `pageSize` | Keep separate |
| `Submissions`, `HistoricalFile` | Backend SEC-loading details | No |
| `FilingsError` | Frontend request-error handling | No |

**I recommend sharing the API response types** in `shared/types/filings.ts`. Both sides would import them, and the backend response-producing function would declare `FilingsResponse` as its return type. This catches contract drift during typechecking.

There’s some TypeScript/build configuration work because the backend currently restricts source files to its own directory. Shared types also don’t validate incoming JSON at runtime. For this repo, the modest setup is worthwhile as more endpoints gain frontend consumers. I haven’t moved the types yet.
