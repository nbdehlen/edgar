Because those paths describe **the files Node will load after compilation**.

This backend uses `"type": "module"` and TypeScript’s `NodeNext` settings. Node’s ES module imports require explicit file extensions, so:

```ts
import { companiesRouter } from './features/companies/routes.js';
```

works at both stages:

- **While developing:** TypeScript resolves `routes.js` to the source file `routes.ts`.
- **After building:** `routes.ts` becomes `routes.js`, and the import already points to the correct file.

That’s the standard pattern for this setup. [TypeScript documentation](https://www.typescriptlang.org/docs/handbook/modules/reference)

Using `.ts` imports is also possible with compiler options that rewrite extensions during builds, but this project currently uses the `.js` convention.
